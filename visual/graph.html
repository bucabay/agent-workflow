agent.default v1.0.0

Evidence-based default agent workflow: cheap parallel read-only exploration -> frontier planning -> delegation-aware implementation (single writer) -> clean-context diff review -> deterministic verification -> bounded fix/replan loop -> report with telemetry.

planllm:plannerPlan (frontier, single writer)Frontier intelligence should be spent on the plan, ambiguity, and final review - not on mechanical volume. | The quality lever is the brief: enumerate constraints, edge cases, and a definition of done. Fable's constraint-rich briefs beat Opus's dictated file contents. | An implementation plan is a first-class artifact you can read, diff, and gate before any side effect fires.
routechoiceRoute by delegabilityDelegation controls what work stays with the expensive model; routing decides whether the expensive model is involved at all. | Forcing delegation decreases performance - it just delegates the wrong things. Delegability is itself a judgment call. | When the judgment IS the deliverable, delegating it backfires (hard React feature scored 27/100). Mechanical work hands off cleanly.
implement_sidekickllm:sidekickImplement (cheap sidekick)Once the plan is fixed, throughput and cost matter more than raw IQ. | Writes must stay single-threaded; parallel writes fragment implicit decisions.
implement_frontierllm:writerImplement (frontier writer)
reviewllm:reviewerReview diff (clean context, other family)A clean-context reviewer with no shared context catches bugs the author cannot see; shorter context = more intelligence on the diff. | Main and sidekick from different vendors means every diff gets an independent second-family read. | The model that wrote the code is often the worst reviewer of it.
verifytoolVerify (deterministic gates)Automated quality gates are structural: each agent's output passes tests before merge eligibility. | Verification is a structural orchestration component separate from execution agents.
quality_gatechoiceQuality gate (bounded retry)Loop generation + evaluation must be bounded; unbounded loops drift. Guard counts loopbacks, exhaust routes to replan.
fixfix_attemptFix loop (bounded)Evaluator-optimizer: loop generation + evaluation; must be bounded to stay accurate. | Bounded multi-attempt retry lifts pass rate (81.2% pass@3 vs single-attempt baselines).

reportllm:plannerReport + telemetry
